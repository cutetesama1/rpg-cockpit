# 0.7.3：提示词与回滚修复

本轮检查代码与合成回归场景，没有读取真实玩家游玩记录，也没有调用用户付费模型。

## 找到的问题

1. 旧协议要求将未知事项写入 uncertain，但 Proposal 又把任何非空 uncertain 判为整批失败，连已确认的伤害也无法提交。
2. 校验失败后的第二次请求只有错误文本，缺少上一份草案和准确出错位置，模型可能修补一处却遗漏其他变化。
3. 旧世界包提示词要求逐个调用内部工具、禁止状态 JSON，与现有单次 settle_turn 草案协议存在冲突。
4. 普通新剧情 flag 虽转为事实，但中文或过长 id、已有 story. 前缀仍会拒绝或重复加前缀。
5. 技能付款的补充提示仍让叙事端“照常调用工具结算”，与纯叙事输出契约冲突。现改为仅描述已发生后果，由独立后端结算。
6. 聊天与结算日志没有呈现待确认事项，玩家容易把无法识别的内容误认为已经结算。

## 当前模型职责

叙事端：读取当前真值、世界设定及最近情节，输出正文与选项。心理、对白与实际行动分清，明确事件结果；不能调用修改状态工具，不能输出资源结算或状态栏。

后端：平常只在正文完成后调用一次，无历史消息。读取当前完整状态、字段与范围、累计限额、资源绑定、目录、已收技能费用及本次最终正文；通过一次 settle_turn 提交增量。只有草案非法时再请求一次完整修正，不额外建立后台记忆或逐领域调用。

世界自定义提示词与存档不覆盖。运行时对已有世界同样注入职责和协议约束，新建世界默认提示词同步更新。

## 修复行为

- 不确定事项作为 settlement.warning 记录，相关未知事项保持原值，其他合法且有证据的变化正常原子提交。聊天显示“待确认，相关状态保持原值”，结算日志也能查看。
- uncertain 不是绕过护栏的许可：若同时提交非法操作，仍拒绝整份草案；不会自动吞掉伤害、库存或技能错误以伪造成功。
- 重试输入包含 previous_proposal、failed_at、错误码与错误详情。要求保留其余有依据的变化，修正后提交完整草案。重试仍从原始权威状态开始，不重复扣已付技能费用。
- 普通事实支持稳定英文id、已有 story. 前缀。中文或过长合法文本名称映射为稳定摘要id，标题保留原文；空id、非法值仍拒绝。这不会注册系统 flag 或解锁场景。
- 所有暂存事件在实际落账前进行事件契约预校验。数值范围、累计限额、证据、物品库存、技能前置、衣物目录、非法立绘字段等护栏保留。

## 验证范围

新增回归包括：不确定项与合法伤害共存、非法操作不允许部分提交、工具调用与JSON回退两种草案的完整修复反馈、中文事实和撤销、旧提示词协议兼容，以及40个连续回合中混合事实更新、待确认事项和8次修复后的状态/账本一致性。

这里的模拟测试验证框架行为，不代表任意第三方模型都不再输出非法草案；真实接口异常或两次均非法仍会回滚，并在结算日志记录位置与原因。

公开发布版继续使用原创静态示意角色，外观接口可供自行接入授权素材；第三方完整立绘库不在本次发布范围。公开版独立构建与验收结果见 docs/releases/v0.7.3-verification.json。
