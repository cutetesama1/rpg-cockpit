# 0.8.1：玩家裁定中心

这是 1.0.0 路线的第二阶段，沿用 0.8.0 的导演与骰子。第三阶段角色卡兼容、第四阶段动态世界书和多人联机尚未实现。

## 使用

网页、桌面与 APK 的侧栏均有“玩家裁定”入口，并显示公开待处理数。主界面仍保留原有叙述和输入布局。

后端本轮结算中确认发生的变化仍自动落账。有歧义的事项进入待裁定队列，保持对应状态；同一事项不应同时放入自动操作和待裁定草案。

选择事项后可预览确认、否决或搁置。搁置后可恢复。界面内有“裁定是什么？如何使用”指引。修改时填写裁定依据：衣物、饰品、损坏程度、动作和表情使用当前目录的选择框；数值状态输入最终数字；颜色使用色板和 R/G/B（0—255）。界面自动选择换装、立绘或状态工具，不必编写操作代码。高级完整草案仍支持物品、技能和场景工具。所有操作沿用目录、前置条件和护栏。

“预览修改草案 → 保存修改草案”只保存建议，不改变游戏状态；之后再“预览确认 → 确认并提交”才会落账。预览会显示字段、库存、角色信息、技能、场景、剧情事实的前后差异。空草案表示仅确认说明，不偷偷补猜测操作。

旧存档的 settlement.warning/uncertain 也会显示在队列中。这些记录没有可执行草案和可信原状态，必须先修改、写依据并预览。

## 状态与事务

后端仍只读取单次最终叙述和当前状态。新增 pending 可选数组：每项 title、reason、evidence、visibility、operations、status_patch。pending 与 uncertain 不应重复，同一变化不能同时自动结算和待确认。

pending 的操作只是建议，未确认前不会执行；公开叙事上下文不包含待裁定草案。未知目录、非法参数、类型错误、资源不足和技能前置不满足均不能通过确认绕过。

预览使用隔离副本和原有结算校验，不访问模型，不写真实账本。提交持有会话锁，核对当前内容包、完整账本版本和预览令牌，重新校验整批变化后才追加事件。拒绝、搁置、恢复和撤销也检查版本与状态迁移。请求编号与完整请求摘要写入回执，同请求重试只返回回执，不重复扣款；同编号改参数返回冲突。

裁定用独立的负数辅助事务编号，普通游戏回合仍为非负数。辅助事务不写 turn.committed，不推进游戏回合或技能冷却。所有状态仍从同一账本投影；负数编号也受现有回合撤销过滤约束。新的预览和操作回执随普通存档保存，恢复后仍可查历史和防重复。

原状态、字段定义或游戏进度变化后，旧建议不能直接确认。必须由玩家按当前状态修改并重新校对，避免把旧绝对值覆盖到新进度。

## 历史、秘密与撤销

历史显示每次操作、理由、时间和前后差异，并保留修改前后草案用于审计。没有游戏进度变化的确认可单独撤销；否决可以撤销并重新打开。撤销已确认裁定会取消它自己的辅助事务，同时恢复状态、库存、习得技能、场景、角色信息与剧情事实。

为避免覆盖后来发生的事件，有后续有效游戏进度或状态操作时阻止直接撤销。可以先撤销后续回合；该回合存在依赖裁定时，需要先在裁定中心撤销裁定。更晚的裁定也应按先后顺序撤销。

公开列表默认排除内部事项；“查看内部事项（含剧透）”必须显式开启。裁定原草案及完整回执不出现在普通事件流、SSE 或导出日志；裁定中心单独返回经过可见性过滤的内容。内部剧情事实不进入公开事实和叙事上下文。

目前是本地单人应用的可见性隔离，不是联网多用户权限系统。完整存档仍包含内部记录，便于恢复游戏；分享存档前应自行了解这一点。

## API

- GET /api/adjudications?include_internal=false
- POST /api/adjudications/{id}/preview
- POST /api/adjudications/{id}/decide

写操作包含 pack_id、include_internal 和 decision。decision 含 request_id、revision、action、reason，修改可包含 operations/status_patch，确认及修改提交必须携带 preview_token。

action：confirm / reject / modify / defer / resume / undo。

原始契约见 contracts/adjudication.schema.json 与 contracts/turn-settlement.schema.json。失败预览不写状态、不触发任何模型调用；失败提交也不能部分执行。


公开版采用原创静态示意角色，可自行接入授权素材。源码和安装包的测试范围以对应版本发布页为准。
