# 0.9.0：角色卡 V2/V3 与裁定指引

通往 1.0.0 的第三阶段已实现；第四阶段“动态世界书维护”尚未实现。

## 如何使用

游戏库 → 导入角色卡 V2/V3 → 选择 JSON、原始 PNG/APNG 或 CHARX → 选择映射 → 预览 → 按预览创建并进入。

卡内角色默认是 NPC，与玩家区分。需要玩家扮演卡内角色时显式选择“玩家扮演的角色”。玩家称呼用于替换 {{user}}；{{char}}、<BOT>、<CHAR> 使用昵称（存在时）或角色名。可在默认、备选和群组开场文本中选择；选项改变后须重新预览。选择群组文本不代表启用了多人联机。

描述、性格、场景映射到前置设定；示例对话与卡内提示映射为叙事参考，示例不会变成已发生事件。框架始终保留叙事与结算分离。卡内提示不能修改工具权限、上限或状态定义。

提供开场白时直接使用所选文本，不再调用模型改写。开场白视作初始叙事，不自动触发伤害、奖励或技能授予；状态和上限可在世界构筑里调整。未提供开场白时继续使用原开局生成流程。

导入与预览不额外调用模型；不会把 NPC 的传奇能力、物品或伤势授予玩家。新世界先有基础探索技能，可在世界构筑中按需要匹配预设技能库与调整玩家能力。

## 已映射与保留

| 内容 | 处理 |
| --- | --- |
| V2/V3 JSON | 自动识别 spec 与版本；新版本按已知字段读取并提示 |
| PNG/APNG | 读取 chara / ccv3 文本块，同时存在时优先 ccv3；校验长度和 CRC |
| CHARX | 读取根 card.json，保留完整原包，不解压执行素材 |
| 描述、性格、场景 | 可选择是否映射；保留原文 |
| 默认、备选、群组开场 | 预览中选择文本；群组文本不启用多人功能 |
| 示例对话 | 作为语气示例，明确不属于实际历史 |
| system_prompt / post_history_instructions | 作为卡内叙事参考；{{original}} 采用框架叙事默认值，不影响结算契约 |
| creator / creator_notes / 版本 | 在预览展示，不加入模型提示词；多语言备注优先显示中文，其次英文 |
| 嵌入式世界书 | 映射到现有世界书条目，保留来源索引；重复原 ID 不会覆盖 |
| keywords / constant / enabled | 字面关键词、常驻、启停 |
| case_sensitive / selective / secondary_keys | 大小写及次级关键词条件 |
| priority / insertion_order | 优先级与同优先级排序；优先级转整数时提示并保留原值 |
| use_regex | 本轮不执行正则；停用该条并明确提示，保留原始条目 |
| @@ 装饰指令 | 停用含这些专属指令的条目并提示，避免错误触发 |
| 扫描深度、预算、注入位置 | 使用框架现有规则；原设置保留并列入兼容提示 |
| extensions / 未知字段 | 原样保存，不执行脚本或其他客户端专属设置 |
| 图片、音频、模型等 assets | 保留引用和原始容器，不远程下载，不自动转换为分层立绘 |

这是一组明确边界的兼容导入功能，不是完整复刻 SillyTavern 的全部扩展、宏和多媒体运行时。

## 原始数据与存档

新游戏目录保存 character-card.json（含原始 JSON、映射设置、兼容报告和来源摘要）、character-card/source.json，以及字节不变的 character-card/source.bin。

游戏库的角色卡面板可导出当前卡原始 JSON、原始文件和兼容报告。导出的“原始 JSON”忠实保留导入数据，不会假装已经合并后续的世界书编辑。完整存档包含角色卡 JSON 与映射信息；若转移存档时未带原始二进制，仍可导出 JSON，二进制导出会明确提示不可用。

已有 ID 不覆盖。提交必须匹配预览令牌和当前游戏；请求编号防止网络重试重复创建或重置游戏。新内容包先在隐藏临时目录校验，再整体移动到用户目录；激活失败会恢复原会话并移除本次新建内容。

文件限制 20 MB、角色卡 JSON 4 MB、世界书 2000 条。JSON 重复键、非有限数字、过深嵌套、PNG 损坏、CHARX 非法路径/加密或异常体积都会给出错误。素材保留不意味着自动执行。

APK 已补充 JSON/图片/CHARX 文件选择，以及原始文件与 JSON 报告的系统保存入口；手机真机仍需要额外验收。

## 裁定界面更新

裁定中心内可直接展开使用指引。固定目录值使用选择框，数值输入最终值，颜色可选色板或输入 RGB。衣物、磨损和颜色自动合并为同一槽位换装草案；数值修正会替换同字段原伤害草案，避免叠加。先保存修改草案，再预览确认。
