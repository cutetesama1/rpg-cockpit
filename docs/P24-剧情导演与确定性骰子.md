# 0.8.0：剧情导演与确定性骰子

这是 1.0.0 路线的第一阶段。裁定中心、角色卡兼容、动态世界书未在本版本实现，进度见 ROADMAP-1.0.0.md。

## 如何使用

设置 → 剧情导演与骰子。启用后选择场景变化、重要事件和线索变化作为触发条件，并保存到当前游戏；默认最少间隔2个已提交回合，手动请求不受间隔限制。
默认复用叙事模型连接。要单独配置导演，关闭复用选项，并在设置的高级模型角色中配置 director 后保存模型设置。
“下回合请求一次导演”只排队，不立即调用模型；在下一次提交玩家行动时执行。
普通静止回合不调用导演，关闭时整个回合调用链仍是叙事加结算。导演异常仅跳过本次候选，不让原本可执行的游戏回合失败。

骰子工具无需模型调用，支持d4/d6/d8/d10/d12/d20/d100、NdM±修正、2d20kh1/kl1、d%和4dF，以及0%至100%概率检定。可选成功阈值。
手动骰子仅记录结果，不直接扣生命、增减物品或代替后续玩家裁定。

## 事件与模型边界

导演只输出候选JSON，不能调用工具，不能直接修改游戏状态或替玩家做决定。候选限制在环境、NPC和线索；模型提示词要求同批候选可同时发生，互斥方向放入同一事件的结果分支。
director.proposed保存原候选；trigger通过后才形成director.triggered；结果检定完成后记录director.resolved。
叙事请求中只有已经确定的公开结果，没有未触发候选、未选中分支或内部秘密。数字检查导致的叙事重写复用同一结果。
当前回合公开的确定结果也提供给结算端核对，不能作为新的正文证据，不能重掷或推翻；所有状态变更仍经过原有结算护栏。

## 确定性与恢复

每个游戏存档拥有私有随机种子，HMAC-SHA256结合事件ID和抽样序号生成结果，拒绝采样避免取模偏差。启用导演时先生成种子，随当前游戏保存。
同事件ID、同参数返回原结果；同ID改参数会拒绝。候选ID在当前存档中只评估一次，不能通过重提同ID获得新的触发机会。
随机审计不跟随游戏回合撤销而删除，所以修复草案、整个回合失败重试、撤销重做及读档都不重掷同一逻辑事件。
游戏回合仍原子提交；未成功提交的触发不会计入已生效剧情，但原始抽样结果保留供后续重试复用。
原有结算阶段roll操作也接到同一确定性服务，自动ID由上一个已提交节点、当前行动、当前初始状态和骰式构成；多个不同检定可显式给出稳定event_id。
失败回合也写自动存档，保留检定凭证和回滚记录。种子与审计留在本地存档中，默认状态、SSE、结算日志导出与调试目录不公开这些记录。

## 线索与内部信息

提供轻量线索参考列表，可手动记录标题、摘要、未解决/已解决/搁置和公开/内部属性。导演读取未解决线索，只能引用已登记ID，不会自行关闭或修改线索。
这不是动态世界书实现，也不是玩家裁定中心。自动维护、变更审核和裁定事务留到后续阶段。
“查看内部记录”是当前单人应用中的显式调试操作，可以看到候选和幕后结果，但不返回随机种子。默认游戏页面和叙事上下文看不到这些数据。

## 接口

- GET/PUT /api/director：读取或保存当前游戏导演设置。
- POST /api/director/request：排队下次行动的导演调用。
- PUT /api/director/clues：维护线索参考。
- POST /api/dice/roll：带事件ID的幂等检定。
- GET /api/director?include_internal=true：单人显式查看内部审计。

有副作用的接口要求pack_id，切换世界后使用旧面板提交会返回409，防止误改另一场游戏。
旧存档无需迁移，缺少导演配置时默认关闭；新功能的设置、线索与记录随事件账本保存。

## 验证

回归包含普通骰型、取高/低、Fate骰、概率边界和非法参数、稳定ID和存档恢复、候选未触发隔离、内部信息隔离、调用频率、失败分支、重试、撤销重做、角色模型配置、API幂等、失败自动存档及SSE隔离。
真实网络模型的文案质量与提示词服从情况不等同于框架契约测试；测试不会调用用户的付费模型。


公开版采用原创静态示意角色，可自行接入授权素材。源码和安装包的测试范围以对应版本发布页为准。
